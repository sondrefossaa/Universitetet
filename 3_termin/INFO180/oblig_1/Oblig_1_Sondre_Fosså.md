## Task 7

Viewing an AI system as an intelligent agent means treating it as something that observes an environment and chooses actions that affect that environment. The agent and environment form a continuous interaction loop. The environment produces information that the agent can perceive, the agent processes this information, and its chosen action may change what it perceives next. An agent is called rational when it selects actions that are expected to achieve its goals as well as possible, given its available information and capabilities. This does not mean that it always succeeds or knows everything about the world.

Inputs to the agent are called percepts. They may come from physical sensors, such as cameras and distance sensors, or from digital sources, such as user messages, database records or game states. Because one percept may not reveal the full situation, an agent can also use a history of percepts or maintain an internal representation of the world. Its outputs are actions. A physical robot may move or grasp an object, while a software agent may recommend a film, answer a question or place an item in a calendar.

The right agent design depends on both the task and the properties of the environment. The designer must decide what counts as success, which observations and actions are available, and whether the environment is fully observable, predictable, static or changing. Time limits and the consequences of mistakes also matter. An agent for chess can inspect the whole board and assume that moves follow fixed rules. A self-driving car, in contrast, receives incomplete and sometimes noisy sensor data while other road users move independently, so it must continually update its beliefs and react quickly.

A robot vacuum is a simple concrete example. Its environment consists of rooms, obstacles, dirt and possibly people or pets. It perceives information through sensors for collisions, distance, dirt and location. It acts by moving, turning, cleaning or returning to its charger. Its design should balance cleaning coverage, time, energy use and safety. A useful vacuum agent therefore needs behavior suited to the particular environment in which it operates rather than a single fixed sequence of movements.

## Task 8

A search problem can be represented as a state space in which each state describes a possible situation. The problem definition includes an initial state, a set of available actions, a transition model that says which state results from an action, a goal test and often an action-cost function. This produces a graph: states are nodes, and legal transitions are edges. Solving the problem means finding a path from the initial node to a goal node. For route planning, a state could be the current city, edges could be roads, and edge costs could represent distance or travel time.

The search strategy determines which frontier node is expanded next, so it can greatly affect memory use, running time and the quality of the result. Breadth-first search (BFS) expands the shallowest nodes first using a first-in, first-out frontier. It is complete when the branching factor is finite, and it finds a path with the fewest edges when every action has the same cost. However, it can consume large amounts of memory because it stores an entire search level. Depth-first search (DFS) instead follows one branch as far as possible before backtracking. It normally uses much less memory, but it can waste time in a deep or infinite branch and does not guarantee the shortest or cheapest solution. Lowest-cost-first search expands the path with the smallest accumulated cost and is optimal when action costs are positive, although it may explore many nodes.

Path length and path cost are different measures. Path length is the number of actions or edges in a path. Path cost is the sum of the costs of those actions. A five-road route can therefore be cheaper than a three-road route if its roads are shorter or faster. BFS optimizes path length under equal costs, while lowest-cost-first search optimizes total cost.

Informed search uses a heuristic to estimate how far a state is from a goal. A* orders nodes by `f(n) = g(n) + h(n)`, where `g(n)` is the cost already paid and `h(n)` estimates the remaining cost. A good heuristic focuses the search toward promising states. A* is cost-optimal under the usual conditions when the heuristic never overestimates the true remaining cost; for graph search, consistency is commonly required so costs do not appear to decrease along a path. Optimality therefore depends on what is being minimized and on the assumptions of the chosen strategy.

## Task 9

A constraint satisfaction problem (CSP) describes a problem through variables, domains and constraints. Each variable represents something that must be decided, and its domain is the set of values it is allowed to take. An assignment gives a value to one or more variables. It is consistent if it does not violate any relevant constraint, and it is complete when every variable has been assigned. A solution is a complete, consistent assignment. For example, in a timetable CSP, variables could represent courses, each domain could contain possible time slots, and constraints could state that courses with shared students cannot occur at the same time.

A basic solver can search through possible assignments, but the number of combinations grows quickly. Consistency algorithms reduce this search space before or during search by deleting domain values that cannot be part of a valid solution. For a binary constraint between variables `X` and `Y`, an arc from `X` to `Y` is arc-consistent if every remaining value of `X` has at least one supporting value in `Y` that satisfies the constraint. If a value has no support, it can safely be removed. A removal may make values in neighboring variables unsupported, so the algorithm repeatedly checks affected arcs until no more values can be removed or a domain becomes empty.

Generalized Arc Consistency (GAC) extends this idea to constraints involving any number of variables. For every value in the domain of each variable in a constraint, there must be some combination of values for the other variables that satisfies that constraint. Propagating these removals can detect failure early and can greatly reduce the branching required by backtracking search. If propagation leaves a variable with only one value, that forced choice can cause further useful pruning.

Local consistency does not always imply that all constraints can be satisfied together. Consider three variables arranged in a triangle, each with the domain `{red, blue}`, and a constraint that every connected pair must have different colours. Every value has support across each individual arc: red is supported by blue, and blue by red. The network is therefore arc-consistent. Nevertheless, two colours cannot colour a three-node triangle, so no global solution exists. Consistency filtering is valuable because it removes impossible values efficiently, but search or stronger forms of reasoning may still be needed to determine whether the remaining locally compatible choices form a complete solution.
